~/overview

What it is, simply

The code behind malloc and free: it hands out chunks of a big block of memory and takes them back.

Every program allocates. A good allocator is fast, wastes little memory and avoids fragmentation; a bad one is a hidden performance tax.

Free listsBoundary tagsSplitting & coalescingFragmentationAlignmentArenasSlabsPools

used in the real world

  • ›glibc ptmalloc, jemalloc (Firefox, Redis), tcmalloc (Chrome, Google), mimalloc
  • ›Linux kernel slab/SLUB allocator
  • ›Game engines and databases (arenas, pools)

alternatives

  • ›Garbage collection
  • ›Region/arena allocation per request
  • ›Size-class segregated allocators

limitations

  • !General-purpose allocators can't beat specialized ones for fixed patterns
  • !Fragmentation can make memory unusable even when plenty is free

~/internals

Learn the internals

01 Boundary tags

Write each block's size at both ends so you can find your neighbours instantly.

Header and footer hold size|allocated-bit. The next block is at addr+size; the previous block's footer is just before the header. That makes coalescing O(1).

common mistake · Omitting the footer: finding the previous block becomes a linear scan.

02 Fragmentation

Lots of free memory, but in pieces too small to use.

External fragmentation = 1 − largest free block / total free. Internal fragmentation = header/padding overhead inside allocated blocks.

common mistake · Reporting only total free bytes — a 50% free heap can still fail a medium allocation.

03 Alignment

Some data must start at addresses divisible by 8, 16 or 64.

Payloads here are 8-byte aligned because blocks are multiples of 8 starting at offset 4 with a 4-byte header. The arena shows the padding cost of 64-byte (cache-line) alignment.

common mistake · Misaligned SIMD loads — slow on some CPUs, a crash on others.

04 Specialized allocators

If all objects are the same size or die together, you can do much better than malloc.

Arena: bump a pointer, free everything at once. Pool: fixed slots, free list threaded through the free slots. Slab: per-size-class pages with bitmaps (the kernel's approach).

common mistake · Using a general-purpose allocator for millions of identical short-lived objects.

~/build

How the C++ version gets built

  1. 01Heap — mmap a region; boundary-tag blocks with explicit segregated free lists.
  2. 02Size classes — Thread-local caches per size class, like tcmalloc/mimalloc.
  3. 03Large objects — Direct mmap above a threshold, returned with munmap.
  4. 04Debugging — Canaries, poison-on-free, double-free detection, leak report at exit.
  5. 05Benchmarks — LD_PRELOAD-able shim to compare against glibc malloc on real programs.
