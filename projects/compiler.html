~/overview

What it is, simply

A program that reads source code in a small language called Tern, checks it for mistakes, translates it into compact instructions, and runs them.

Every programming language you use is built from these same parts. Building one demystifies errors, performance and memory management.

LexingPratt parsingASTType checkingConstant foldingBytecodeStack VMMark-sweep GC

used in the real world

  • ›CPython, Lua, Ruby YARV (bytecode VMs)
  • ›V8, JVM HotSpot (bytecode + JIT)
  • ›clang/LLVM, rustc front-ends (lexer, parser, type checker)
  • ›SQL engines, regex engines, shader compilers

alternatives

  • ›Tree-walking interpreter (simpler, slower)
  • ›Compiling to native code via LLVM
  • ›Register-based VMs (Lua 5, Dalvik)

limitations

  • !No closures or globals in functions (deliberate simplification)
  • !Only int, bool and [int]
  • !No JIT

~/internals

Learn the internals

01 Precedence climbing

Decide that * binds tighter than + by giving each operator a number.

parse an operand, then while the next operator's precedence is higher than the current minimum, consume it and recursively parse the right side with that precedence.

common mistake · Using ≥ instead of > makes left-associative operators right-associative: 8-4-2 becomes 6.

02 Type checking

Catch '1 + true' before the program runs.

Walk the AST with a stack of scopes mapping names to types; each expression returns its type; mismatches are reported with positions. Non-void functions must return on every path.

common mistake · Reporting only the first error — collecting all of them is far more useful.

03 Bytecode & back-patching

Write a jump before you know where it lands, fill in the address later.

if/while emit JZ with a placeholder, compile the body, then patch the target. && and || compile to DUP + conditional jump for short-circuiting.

common mistake · Evaluating both sides of && — 'false && 1/0' must not divide.

04 Mark-sweep GC

Find everything still reachable, throw away the rest.

Roots are the VM stack (locals + temporaries). Mark reachable objects, sweep unmarked ones, grow the next threshold to 2× live objects.

common mistake · Forgetting roots: an object only referenced from a register/temporary gets freed while in use.

~/build

How the C++ version gets built

  1. 01Front-end — Hand-written lexer and Pratt parser in C++20 with std::variant AST nodes and arena allocation.
  2. 02Semantics — Type checker + SSA-style IR for optimizations (constant propagation, DCE, inlining).
  3. 03Back-end — Compact bytecode with a computed-goto dispatch loop.
  4. 04Memory — Precise mark-sweep GC with shadow-stack roots, later generational.
  5. 05JIT (optional) — Template JIT for hot loops via a small x86-64/arm64 emitter.
