~/overview

What it is, simply

The part of a database that reads your SQL, figures out the fastest way to answer it, and runs that plan.

The same query can take milliseconds or hours depending on the plan. Understanding planners explains why indexes and statistics matter.

~/internals

Learn the internals

01 Predicate pushdown

Throw rows away as early as possible.

WHERE conjuncts that mention one table are evaluated inside that table's scan, so the join sees fewer rows. Conjuncts spanning both tables stay above the join.

common mistake · Filtering after the join: the join does work on rows that are discarded anyway.

02 Join algorithms

Three ways to match rows from two tables.

Nested loop compares every pair (L×R). Hash join builds a hash table on one side and probes with the other (L+R). Sort-merge sorts both and walks them together (good when inputs are already sorted).

common mistake · Nested loops on large inputs — the mini engine refuses beyond 8M comparisons to make the point.

03 Cost model

Guess how many rows each step produces, pick the cheapest plan.

Selectivity of col = literal ≈ 1 / distinct(col); ranges ≈ 1/3. Join output ≈ L×R / max(distinct keys). Costs: hash 1.2·min + max, sort-merge n log n, nested L×R.

common mistake · Stale statistics: estimates off by 100× lead to the wrong join order.

04 Vectorized execution

Process 1024 values at a time instead of one row at a time.

Operators exchange column batches; tight loops over arrays are cache- and branch-friendly and amortize interpretation overhead (the DuckDB/MonetDB/X100 idea).

common mistake · Batches too small (overhead dominates) or too large (falls out of cache).

~/build

How the C++ version gets built

  1. 01Parser — Hand-written SQL parser producing a typed AST; error recovery with positions.
  2. 02Binder + catalog — Schema catalog, type resolution, histogram statistics.
  3. 03Optimizer — Rule-based rewrites + cost-based join ordering (DPsize for small joins).
  4. 04Execution — Vectorized operators over Arrow-like column vectors with selection vectors.
  5. 05Storage — Columnar files with zone maps, dictionary and RLE compression.
