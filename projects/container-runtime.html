~/overview

What it is, simply

A program that starts processes inside 'containers': they get their own view of process IDs, hostname, files and network, and hard limits on CPU and memory.

Containers let many apps share one machine without seeing or starving each other — cheaper and faster than virtual machines.

Namespacescgroups v2pivot_rootOOM killerCPU throttlingveth + bridgeUser namespaces

used in the real world

  • ›runc / crun (the OCI runtimes under Docker, containerd, Kubernetes)
  • ›youki (a Rust OCI runtime)
  • ›systemd-nspawn, LXC
  • ›Sandboxing in CI systems and serverless platforms

alternatives

  • ›Virtual machines (stronger isolation, heavier)
  • ›gVisor (user-space kernel)
  • ›Firecracker microVMs
  • ›WebAssembly sandboxes

limitations

  • !All containers share one kernel — a kernel bug can break isolation
  • !Root in a container without a user namespace is host root
  • !cgroups limit resources, they don't make them faster

~/internals

Learn the internals

01 Namespaces

Give a process its own private copy of a list the kernel keeps — process IDs, hostname, mounts, network.

Each namespace kind virtualizes one resource. A process in a new pid namespace is pid 1 there but has a normal pid on the host; the host can see it, it can't see the host.

common mistake · Thinking namespaces limit resources. They only change what you can see; cgroups limit what you can use.

02 cgroups v2

A budget for a group of processes: this much memory, this much CPU, this many processes.

memory.max triggers the OOM killer within the group; cpu.max 'quota period' throttles the group once it used its quota in the current period; pids.max makes fork() fail with EAGAIN.

common mistake · Setting a CPU limit and expecting latency to improve — throttling adds latency spikes at period boundaries.

03 pivot_root vs chroot

Swap the root filesystem out from under the process so the host's files are unreachable.

chroot just changes path resolution and is escapable by root. pivot_root moves the old root away inside a private mount namespace so it can be unmounted entirely.

common mistake · Using chroot for isolation.

04 User namespaces

Be 'root' inside the box while being a nobody outside it.

uid_map '0 100000 65536' maps container uid 0 to host uid 100000. Capabilities are only valid inside the namespace.

common mistake · Running containers as root without a user namespace — an escape lands as real root.

~/experiments

Guided experiments

Run these in the playground above. Write down what you expect before you start.

  1. E1 Exhaust memory

    objective ·
    See memory.max and the OOM killer act within the cgroup only.
    do ·
    Start a 64 MB container, allocate 30 MB, then 40 MB.
    expect ·
    The second allocation is OOM-killed; memory.events shows oom_kill 1; the host is unaffected.

  2. E2 Throttle CPU

    objective ·
    Observe CFS bandwidth control.
    do ·
    Set cpu 30%, start 4 spinning processes, advance time.
    expect ·
    Usage settles at ~30% of one core; nr_throttled grows every period.

  3. E3 Fork bomb

    objective ·
    pids.max as a safety net.
    do ·
    fork 100 with pids.max 10.
    expect ·
    fork fails with EAGAIN after 9 children; host `ps` still works.

  4. E4 Network isolation

    objective ·
    Compare network=none vs bridge.
    do ·
    Ping between two bridge containers and from an isolated one.
    expect ·
    Bridge containers reach each other; the isolated one is unreachable.

~/build

How the Rust version gets built

  1. 01Spec + bundle — Parse a minimal OCI config.json; unpack an image tarball into a rootfs directory.
  2. 02Namespaces — nix::sched::clone with namespace flags; a sync pipe so the parent writes uid_map/gid_map before the child continues.
  3. 03Filesystem — Private mount propagation, bind-mount rootfs, pivot_root, mount proc/sysfs/devtmpfs, umount2 old root.
  4. 04cgroups v2 — Create a leaf cgroup, write controllers, move the child pid into cgroup.procs.
  5. 05Networking — netlink: create veth pair, move one end into the child's net ns, attach the other to a bridge, assign IPs.
  6. 06Safety — Runs only on a dedicated isolated Linux host, never on the shared execution pool (spec requirement).
