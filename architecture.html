~/layers

Five layers, clearly separated

  1. L1

    Frontend

    Vercel

    Next.js · TypeScript · Tailwind · React Flow · Monaco · Recharts

    • ›Learning UI, architecture diagrams, code explorer
    • ›Experiment configuration and execution controls
    • ›Live metrics, logs and event timelines over WebSocket/SSE

    rule · Never executes native C++/Rust binaries.

  2. L2

    Control plane

    Linux compute

    Rust · Axum · PostgreSQL · WebSockets

    • ›Auth, users, progress, experiment history
    • ›Validates configs against each system's manifest
    • ›Orchestrates executions, enforces quotas and timeouts, aggregates telemetry

    rule · Contains no project-specific logic — systems are described by manifests.

  3. L3

    Execution layer

    Isolated containers

    Docker · one image per system · execution agent

    • ›Runs the real C++/Rust systems
    • ›Standard lifecycle: start, stop, restart, reset, configure, execute, workload
    • ›Streams events and metrics through the agent

    rule · Never exposes the Docker socket, a shell, or privileged containers to users.

  4. L4

    Observability

    Prometheus · Grafana · OTel

    Structured JSON logs · traces · metrics

    • ›CPU, memory, network, disk per execution
    • ›Throughput, latency percentiles, error rates
    • ›Project-specific metrics (replication lag, poll counts, consumer lag…)

    rule · No fabricated or static metrics in production mode.

  5. L5

    Persistent storage

    Managed Postgres + object storage

    PostgreSQL · S3-compatible storage

    • ›Users, experiment configs, execution history, benchmark summaries
    • ›Large artifacts and reports in object storage

    rule · Postgres never substitutes for the storage engines being built.

~/contract

One execution contract for ten different systems

Standardize the outside, keep the inside honest. Every system ships one binary in its own image and speaks the same protocol, whatever its language — so the control plane needs zero project-specific code.

conceptual lifecycle (Rust)

trait SystemExecutor {
    async fn start(&self, config: Config) -> Result<ExecutionId>;
    async fn stop(&self, id: ExecutionId) -> Result<()>;
    async fn restart(&self, id: ExecutionId) -> Result<()>;
    async fn reset(&self, id: ExecutionId) -> Result<()>;
    async fn status(&self, id: ExecutionId) -> Result<Status>;
    async fn metrics(&self, id: ExecutionId) -> Result<Metrics>;
    async fn logs(&self, id: ExecutionId) -> Result<Vec<LogEntry>>;
}

~/lifecycle

Execution lifecycle

  1. idle
  2. →provisioning
  3. →starting
  4. →running
  5. →stopping
  6. →completed
  7. →failed
  8. →timed out

User configures → control plane validates against the system's manifest → agent provisions an isolated container → the system starts and emits events → the agent forwards telemetry → the browser visualizes it live → stop or timeout releases everything and stores the results. A heartbeat lease means a closed tab never leaves a workload running.

~/security

Security model

  • ◆Authenticated users only; per-user quotas (concurrent + daily executions)
  • ◆Per-container CPU, memory and pids limits; read-only rootfs; all capabilities dropped; no-new-privileges
  • ◆Hard execution timeout + heartbeat lease: a closed browser stops the run within a minute
  • ◆Internal-only container networks — no egress
  • ◆Commands allowlisted per system manifest; no shell anywhere
  • ◆Privileged experiments (container runtime) only on a dedicated isolated host
  • ◆Audit log of every start, stop and failure injection
